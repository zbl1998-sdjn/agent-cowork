## 二、⚠️ 演示风险 + 应对(必看)

1. **MASE 启动依赖环境变量(最关键)**
   MASE 只有在 app 继承了用户级 `MASE_*` 环境时才拉起;**从桌面快捷方式启动会继承,没问题**。但 MASE 没连时是"静默无记忆、零提示"——会让"记忆承接"演示当场失败且看不出原因。
   → **演示前必做**:快捷方式启动后,先发一句"记住 X",再开新一轮问"我刚让你记住了啥",能答对 = MASE 在线;否则用快捷方式重启再试。

2. **Kimi 429 / 模型可用性**
   高频演示可能触发限流 → 对话变慢/失败(刚才调用是 200 正常)。
   → 开演前 5 分钟先 warm 一次;别连点;备一句"主模型故障会自动降级到备用/本地"的话术兜底。

3. **首条延迟**:刚启动时 MASE 冷启 + 首个 Kimi 调用偏慢。
   → 正式开始前先发一条废消息,把链路热起来。

4. **多窗口重叠**:app 偶尔出现两个重叠窗口,显乱。
   → 开演前最大化一个窗口、关掉多余的。

5. **当前跑的是本地重建版**(为修引用文件按钮重建了 desktop + host;测试全绿、已验证),不是正式安装包。
   → 演示没问题;心里知道是 dev-built;改动在本地分支 `0791ea2`。

6. **泄露的 Kimi 配置密钥**(本轮之前的自报项):**公开演示前务必轮换 API key**——安全红线,也是面试官看重的点。

7. **共享屏幕的桌面环境**:桌面有 Kali 工具、一堆图标、卫星图壁纸,共享时显乱。
   → 清桌面 / 换中性壁纸 / 只共享 app 窗口。

## 三、💡 演示流程建议(面试官会盯什么)

- **开场打主打牌——记忆承接**:新窗口设暗号 → 问"第一句"→ 准确复述;再开第二个窗口 → 证明不串台。一招同时展示串台修复 + 产品价值(上下文治理)。
- **取消 P0 的方法论故事**:单测绿 ≠ 完成,live 才发现 55s → 0.4s——最值钱的工程信号。
- **安全四件套**(注入 / 审批 / 路径 / 取消)按 60–90 秒话术讲。
- 被问"你 live 验过吗"——答"验过,而且是查 DB ground truth + 真机实测",不是单测。
- **主动交底 = 加分**:验收记录里的自我纠错(重新发现 P0、自报密钥泄露)正是严谨证据,主动说。
