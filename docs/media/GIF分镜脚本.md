# README 主 GIF 分镜脚本（目标 ≤ 30 秒，demo.gif）

目的：让一个带着怀疑心的陌生访客在 30 秒内看到三件事——**真的能跑、写操作有审批门、安全状态可见**。这三件事是本项目区别于"聊天壳"的核心证据。

## 录制前准备（10 分钟）

1. `npm run start:mvp` 起本地工作台（http://127.0.0.1:3017）。
2. **用干净演示工作区**：确认 trusted root 指向 `build/mvp-workspace`（start:mvp 默认），不要用真实个人目录——GIF 里出现的所有文件路径都会被外人放大看。
3. 往工作区放 2–3 个演示文件（如 `会议记录.txt`、`销售数据.csv`），文件内容用虚构数据。
4. 关闭无关会话历史（左侧"最近"列表里不要出现私人对话标题）。
5. 模型走本机 Ollama（README 快速开始下方的环境变量示例），保证录制时不依赖网络。
6. 录屏工具：ScreenToGif（Windows，免费）；画布 1280×800；帧率 15fps 足够。

## 分镜（5 幕，共 ~28 秒）

| 幕 | 时长 | 画面 | 要点 |
|---|---|---|---|
| 1 | 4s | 工作台首页，鼠标移过"今天想完成什么？"任务卡（写周报/表格急救/会议纪要） | 展示这是完整产品不是 demo 页；停顿让观众看清品牌名 |
| 2 | 5s | 点"会议纪要"卡（或输入框输入："把 会议记录.txt 整理成行动项清单，存成 Word"），点发送 | 输入要短、一眼能读完 |
| 3 | 7s | 执行动态流出现：读取文件 → **生成计划 → 出现审批卡片**。鼠标悬停在审批卡片上停 1.5s，再点"批准" | **全片核心帧**：写操作停下来等人批准。悬停停顿是为了让截帧的人能抓到这一帧 |
| 4 | 7s | 批准后执行继续：写入产物 → 打开"产物"面板，看到新生成的 `.docx`，点开预览 | 证明产出是真文件不是聊天气泡 |
| 5 | 5s | 鼠标移到**安全状态条**（当前安全档位 + 外发字节数），最后停在审计文件提示（`.AgentCowork/security/egress-audit.jsonl`） | 收尾在差异点上：出站可见、留痕可查 |

## 录制后

- 导出 GIF ≤ 8MB（GitHub README 内联上限体验线）；超了就降到 12fps 或裁掉幕 1。
- 存为 `docs/media/demo.gif`，把 README 里 hero.png 的引用替换为 demo.gif（hero.png 保留作 fallback）。
- 发布前逐帧过一遍：确认没有真实路径、真实姓名、真实数据、API key 弹窗。

## 备选：终端版 30 秒（给开发者受众的第二 GIF，可选）

`git clone → npm install → npm run start:mvp` 三条命令实录（用 Windows Terminal，字体调大到 16pt），结尾切到浏览器自动打开工作台的瞬间。这条证明"README 的快速开始不是摆设"。
