# Agent Cowork 面试演示配置说明

这份说明面向面试展示。目标不是把项目包装成“什么都已上线”,而是把架构边界、可运行路径、配置取舍和验收证据讲清楚。

## 1. 一分钟架构讲法

Agent Cowork 是本地优先的 agentic cowork 桌面系统。它分三层部署:

- Tauri 桌面外壳:负责窗口、sidecar 启动、系统打开文件等原生能力,不放业务逻辑。
- Node Host:负责 HTTP/SSE API、Agent tool loop、审批、沙箱、存储、连接器、模型配置和安全边界。
- React UI:负责工作台交互和状态呈现,只通过 Host API / Tauri invoke 通信,不直接 import Host 代码。

Host 内部按 `plan/00-架构基线与模块依赖.md` 分层:L0 安全/HTTP/工具函数,L1 领域能力,L2 运行时状态,L3 路由,L4 装配入口。依赖只能向内/向下,`npm run check:arch` 会守住这个方向。

## 2. 面试前必配和可选项

| 场景 | 必配项 | 说明 |
| --- | --- | --- |
| 离线本地演示 | 不需要 API key | 可展示文件树、写入 preview、审批、产物、UI smoke 和大部分门禁。 |
| 真实模型演示 | 本机 Ollama/LM Studio + 已拉取模型 | 当前 beta 的可执行主路径；使用回环 Base URL，不需要 API key。 |
| 端口冲突 | `PORT=3017` 或其他空闲端口 | Tauri sidecar 默认 3017;普通 Host 入口未配置时默认 3001。 |
| 指定工作区 | `TRUSTED_ROOT=<path>` | Host 只能访问 trusted root 内路径,用于解释 path jail。 |
| SQLite 本地持久化 | `KCW_STORE=sqlite`, `KCW_SQLITE_PATH=<file>` | 适合展示本地持久状态,无需外部服务。 |
| 多实例状态演示 | `KCW_STORE=postgres`, `DATABASE_URL=<url>` | 需要先准备数据库和迁移,不要把它说成默认本地能力。 |
| GitHub 连接器 | `KCW_GITHUB_OAUTH_CLIENT_ID=<public id>` | device flow 不需要 client secret,token 留在 Host 凭证仓库。 |
| Docker 沙箱演示 | `KCW_SANDBOX_DOCKER_IMAGE=sha256:<64 lowercase hex>` | 只接受已拉取镜像的本地不可变 image ID 或 `repository@sha256:digest`;mutable tag 会被拒绝。缺失时会诚实回退并提示网络不隔离，严格模式同时阻断高风险执行。 |

推荐从 `.env.example` 复制一份 `.env`,只填写当前演示需要的项。不要改 `.env.example` 存真实 key。

## 3. 推荐演示顺序

1. 先讲模块边界:
   - `plan/00-架构基线与模块依赖.md`
   - `apps/host/src/runtime/host-state.ts`
   - `apps/windows-client/src-tauri/src/config.rs`
2. 启动 Web/Host MVP:

```powershell
npm run demo:mvp
```

3. 手动演示协作闭环:
   - 选择 trusted root。
   - 发起一个整理/总结类任务。
   - 展示计划、写入 preview、审批、产物和 `.AgentCowork` 审计记录。
4. 如要展示真实模型，先启动本机 Ollama/LM Studio，再按 `.env.example` 配置回环端点；公网 Kimi smoke 当前只保留为待后续审批回执链完成后的外部验收脚本，不要在本轮演示中运行或宣称通过。

```powershell
$env:SECURITY_MODE = 'local_strict'
$env:KCW_MODEL_PROVIDER = 'openai/local'
$env:KIMI_BASE_URL = 'http://127.0.0.1:11434/v1'
$env:KIMI_MODEL = 'qwen2.5:0.5b'
npm run start:mvp
```

5. 如要展示桌面端,先做资源级或 readiness 证据:

```powershell
npm run smoke:windows-resources
npm run verify:windows-readiness
```

原生窗口级 smoke 可能受 Windows Defender ASR 策略影响。没有精确 exe 放行证据时,只能说“资源级/ready 检查通过,窗口级待本机安全策略放行后验收”。

## 4. 面试中可以重点讲的工程点

- 安全边界:trusted root jail(含 Windows 文件名等价/NTFS ADS 归一防绕过)、symlink 解析、敏感路径段拒绝、Host 头白名单、Bearer/JWT/opaque session、写操作幂等键。
- 安全模式与出口治理:5 档安全模式(`local_demo`/`local_strict`/`enterprise_local`/`air_gap`/`controlled_hybrid`)+ 统一出站网关对模型/WebFetch/WebSearch/连接器出口做策略判定与审计,前端安全状态条实时展示「外发 N B」;`local_strict`/`air_gap` 下对外网络工具与非隔离沙箱执行会被自动拦截。
- 记忆安全:MASE/内置记忆写入统一过 DLP 分级拒绝疑似凭据,注入模型前再做读侧脱敏兜底,记忆暂停/隐身开关对所有记忆源一致生效——可以现场演示"贴一段假 API key 进对话,记忆不会存、也不会被后续轮次读出"。
- 可观察性:SSE 事件、run index、审计 JSONL、产物面板、smoke 报告写入 `build/` 或 `reports/`。
- 稳定性:CircuitBreaker、Token Bucket、并发限制、approval TTL、优雅停机。
- 扩展性:MCP tool registry、GitHub OAuth device flow、SQLite/Postgres 后端切换、provider/fallback 模型配置。
- 桌面产品化:Tauri sidecar、Node host 打包、Windows readiness、Defender ASR 风险边界。
- 工程纪律:架构门禁、文件大小门禁、密钥扫描、TypeScript 检查、UI/资源双门禁。

## 5. 验收口径

本地代码门禁:

```powershell
npm run check
```

功能 smoke:

```powershell
npm run smoke:host
npm run smoke:rendered-ui
npm run smoke:react-connectors
npm run smoke:plan-loop
```

完整测试:

```powershell
npm test
```

对外表述要分清:

- `npm run check` 通过:说明架构、类型、lint、密钥、资源和边界门禁通过。
- `npm test` 通过:说明 Host/UI 自动化测试通过。
- 本机 Ollama/LM Studio 真实对话 smoke 通过:只说明当前本机模型路径可用；公网模型仍需独立的审批回执链与授权外部验收。
- 安装包或原生窗口 smoke 通过:才说明当前机器安全策略允许完整桌面验收。

如果某一步因为网络、API key、Docker、Defender 或数据库环境缺失未跑,面试中应说“待真实环境验收”,不要把本地静态门禁说成生产验收。
