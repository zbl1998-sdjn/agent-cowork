## 问题①:拖拽文件到窗口无反应

**根因(高置信):整个 UI 只有底部那条小小的输入框(`.composer`)是 drop 区,没有窗口级拖放区。拖到主窗口/对话区等任何其它地方 → 没有 handler → WebView2 走默认(忽略/打开文件),所以"没反应"。**

证据:
- 拖放 handler **只在** `ui/src/components/Composer.tsx:117-119`(`onDragOver/onDrop→addFiles`),作用在 `.composer` 这一个 div 上。
- 全 UI **没有任何** window/document 级 drop 监听(grep 零命中)。
- `.composer` 是底部圆角输入条(`styles.css:121`,在 `.composer-dock` 内,max-width 820px),**目标区很小**。
- WebView2 侧 `AllowExternalDrop` **默认是 TRUE**(`webview_bridge.cpp` 控制器未改它)→ **webview 本身允许接收拖放**,所以不是原生壳的锅。

**修法(前端,无需重编原生壳)**:加一个**窗口级拖放区**——在 `App.tsx`(或根容器)挂 document/window 级 `dragover`(preventDefault)+ `drop`(取 `e.dataTransfer.files` 交给现有 `addFiles`),并显示全屏 drop 提示。这样拖到窗口任何位置都能接住。

**待实测确认**:拖文件**精确落在底部输入条上**时是否能成功(若连这都不行,才需怀疑更深的 WebView2 层)。明日开 DevTools(现 `webview_bridge.cpp:133` 关着)看 drop 事件是否触发即可一锤定音。

## 问题②:.md 文档"不支持上传"

**根因(中高置信):.md 上传其实不被拦、能成功落盘;问题是上传后只把文件「路径」拼进 prompt,agent 不会自动去读 → 体感像"没支持"。**

证据:
- 后端阻断名单 `uploads.ts:50-54` `BLOCKED_UPLOAD_EXTENSIONS` 封的是 `.exe/.js/.html/.svg/.bat...`,**`.md` 不在其中 = 放行**。
- 前端不挑类型(`Composer.tsx` addFiles)、`fileToUpload`(`lib/api/files.ts:34`)纯字节 base64、`importUploadedFiles`(`uploads.ts:93`)把文件写到 `<trustedRoot>/Agent_Cowork上传/<批次>/`。**全链路对 .md 无报错路径。**
- 上传后 `App.tsx:142` 只追加 `[已上传文件]\n<绝对路径>` —— **给的是路径,不是内容**。

**修法(前端/提示层,无需重编原生壳,二选一或叠加)**:
1. 改 `App.tsx:142` 的提示,明确指示 agent **先用读取工具查看上传文件再处理**(MASE 风格:按需读、不灌全文);或
2. 对文本类小文件(.md/.txt)上传后**自动触发一次读取/入库**。

**待实测确认**:传一个 .md 时——附件 chip 是否出现?是否报错?agent 拿到路径后会不会自己读?(决定是用修法 1 还是 2。)

## 总结

| 问题 | 根因 | 是否动原生壳 | 修法层 |
|---|---|---|---|
| 拖拽无反应 | 只有 composer 是 drop 区,无窗口级拖放 | **否** | 前端加 window 级 drop |
| .md "不支持" | 能传能落盘,但只给 agent 路径、不自动读 | **否** | 前端改提示 / 自动读取 |

**两者都不需要重编 C++ 原生壳**(我之前"高置信壳层 bug"的判断已纠正:壳层 AllowExternalDrop 默认开,没问题)。修法都在前端(vite 重编即可),风险低。建议明日:先 GUI 实测复现 + 开 DevTools 确认 → 再按上面修 → UI 重编 → 实测。
