# Agent Cowork 2.3 小白用户日常办公协作傻瓜化优化计划

> 版本：v2.3  
> 日期：2026-07-02  
> 主题：普通白领 / 办公小白 / 日常协作 / Word、Excel、PPT 傻瓜化 / 一键完成 / 安全可撤回  
> 产品方向：把 Agent Cowork 从“专业 Agent 工作台”进一步升级为“小白也能用的日常办公协作助手”。

---

## 0. 这版计划解决什么问题

前几版计划已经覆盖了 SaaS 化、本地优先、安全保密、国产模型适配、Skills、Recipes、Hooks、记忆、兜底、按需安装、Design 插件和普通白领场景。

这一版继续往下落：**不要假设用户会写 Prompt、会配置模型、会理解文件路径、会用 Excel 公式、会做 Word 排版、会做 PPT 结构。**

目标用户画像非常明确：

- 会打开电脑，但不懂目录结构。
- 会打字、复制、粘贴、发微信、玩游戏，但不会系统性办公。
- Word 只会写字，不会排版、目录、页眉页脚、表格、批注。
- Excel 只会填格子，不会公式、筛选、透视表、数据清洗、去重、合并。
- PPT 只会套模板，不会提炼结构、统一版式、配图、讲稿。
- 遇到报错只会截图问别人。
- 老板给一句“你整理一下”“做个表”“出个 PPT”“弄个周报”，用户不知道从哪开始。

所以 Agent Cowork 2.3 的核心不是“给会办公的人提效 20%”，而是：

> **让不会办公的人，也能把日常工作交付做到 70 分以上。**

## 1. 产品定位调整

### 1.1 旧定位

```txt
本地优先的 Agentic Cowork 系统，帮助用户完成本地文件操作、代码执行和跨工具协作任务。
```

### 1.2 新增面向小白的定位

```txt
一个傻瓜式日常办公协作助手。
用户只需要说“帮我整理一下”“帮我做个表”“帮我弄个 PPT”“帮我写个周报”，系统自动判断任务类型，带用户一步一步确认，最后生成 Word、Excel、PPT、PDF、邮件草稿、群消息草稿、待办清单或项目看板。
```

### 1.3 对外一句话

```txt
不会 Office 也没关系，把文件拖进来，告诉它你要交什么，Agent Cowork 帮你整理、排版、做表、出 PPT、写总结。
```

## 2. 设计原则：小白优先

### 2.1 不让用户做的事

| 不让小白用户做 | 产品应该怎么做 |
|---|---|
| 不让用户写复杂 Prompt | 给用户按钮、示例句、任务模板 |
| 不让用户配置环境变量 | 模型、能力包、工作区都用向导 |
| 不让用户理解 Markdown / JSON / API | 全部包装成“生成文档 / 生成表格 / 生成 PPT” |
| 不让用户看技术报错 | 报错翻译成人话，并给“重试 / 换方案 / 导出草稿” |
| 不让用户手动找文件路径 | 用“文件篮”和最近文件推荐 |
| 不让用户判断该用 Word 还是 Excel | 系统根据输入内容推荐产物类型 |
| 不让用户直接覆盖原文件 | 默认另存为副本，可预览，可撤回 |
| 不让用户决定复杂权限 | 默认最小权限，危险操作先解释再确认 |
| 不让用户面对空白页 | 首页直接给任务入口、最近任务、推荐操作 |

### 2.2 必须做到的事

```txt
1. 一看就知道点哪里。
2. 点错了可以撤回。
3. 不懂也能继续下一步。
4. 失败了也能拿到一个可用草稿。
5. 每次只问一个问题。
6. 所有专业词都翻译成人话。
7. 写入、删除、发送、覆盖必须确认。
8. 优先生成副本，不破坏原文件。
9. 所有产物放在清晰的“成果”区域。
10. 用户不用知道模型、token、MCP、Hook、Recipe 是什么。
```

## 3. 参考 Claude Cowork 后，这版应该重点学什么

Claude Cowork 的公开定位是：用户给一个目标，Cowork 可以在电脑、本地文件和应用上工作，最终交付完成产物。它还强调 Projects、Scheduled Tasks、Spreadsheets、Presentations、从任何地方派活、连接器优先、浏览器其次、Computer Use 兜底等能力。

Agent Cowork 应该参考的是**产品体验层**，不是简单复制能力名：

### 3.1 参考点一：任务不是聊天，而是“交付”

小白用户不需要一个聊天机器人，他们需要：

```txt
我把材料给你，你给我一个能交差的东西。
```

因此首页不要是空白聊天框，而是：

```txt
你今天想完成什么？
[做个表格] [写个文档] [做个PPT] [整理文件] [写周报] [会议纪要]
[老板让我“整理一下”] [我也不知道该怎么弄]
```

最后一个按钮非常重要：**“我也不知道该怎么弄”**。这就是小白真实需求。

### 3.2 参考点二：项目空间要变成“小白文件盒”

Claude Cowork 的 Projects 是带文件、上下文、指令和记忆的工作区。Agent Cowork 应改造成更小白的概念：

```txt
文件盒 / 工作盒 / 项目盒
```

用户不需要理解 workspace。用户只需要知道：

```txt
这个盒子里放的是“本周周报”的材料。
这个盒子里放的是“客户A”的材料。
这个盒子里放的是“报销”的材料。
```

### 3.3 参考点三：周期任务要做成“自动提醒 + 自动草稿”

小白用户很适合周期任务，但不适合全自动发送。

建议产品话术：

```txt
每周五下午 4 点，自动帮你整理本周材料，生成周报草稿。你确认后再发送。
```

红线：

```txt
自动生成可以，自动发送不行。
自动汇总可以，自动删除不行。
自动提醒可以，自动提交不行。
```

### 3.4 参考点四：连接器优先，屏幕操作兜底

Claude Cowork 的思路是连接器优先、浏览器其次、Computer Use 再兜底。Agent Cowork 也应该这样：

```txt
优先：本地文件 / Office 文件解析 / WPS 或 Office API / 飞书钉钉企业微信连接器
其次：浏览器打开网页并辅助复制
最后：屏幕点击自动化，仅限低风险场景，并且每一步可见、可暂停
```

对小白来说，屏幕自动化看起来很神奇，但风险也高。P0-P1 阶段不要把“自动操作屏幕”作为卖点，应把“生成可复制草稿”和“打开目标位置”作为主路径。

## 4. 小白用户最常见的 30 个真实办公痛点

### 4.1 Word 类

| 痛点 | Agent Cowork 应该怎么帮 |
|---|---|
| 不会排版 | 一键统一标题、字体、间距、编号、页眉页脚 |
| 不会写正式语气 | 把口语内容改成正式通知/报告/说明 |
| 不会做目录 | 自动识别标题层级并生成目录 |
| 不会写总结 | 从资料中提炼背景、过程、结论、风险、下一步 |
| 不会写通知 | 选择“通知模板”，填几个字段自动生成 |
| 不会写方案 | 选择“方案模板”，自动生成结构和内容 |
| 不会改错别字 | 自动校对错别字、标点、病句 |
| 不会做合同/制度摘要 | 自动提炼关键条款、风险、待确认问题 |
| 不会把聊天记录变正式文档 | 从聊天/会议口语转成正式纪要 |
| 不会把多个 Word 合并 | 合并、去重、统一格式、生成最终版 |

### 4.2 Excel 类

| 痛点 | Agent Cowork 应该怎么帮 |
|---|---|
| 不会公式 | 直接问“你想算什么”，自动写公式或直接算出结果 |
| 不会筛选 | 用自然语言筛选：“找出本月未付款客户” |
| 不会去重 | 自动识别重复行，生成去重预览 |
| 不会合并表格 | 自动按姓名/手机号/订单号匹配合并 |
| 不会数据清洗 | 清理空格、错别字、日期格式、金额格式 |
| 不会做汇总 | 一键按部门、人员、月份、客户汇总 |
| 不会做图表 | 自动推荐柱状图、折线图、饼图，并解释用途 |
| 不会找异常 | 自动标出缺失、重复、金额异常、日期异常 |
| 不会透视表 | 产品不要说“透视表”，说“按类别统计” |
| 不会做日报/周报数据 | 从表格自动生成文字结论 |

### 4.3 PPT 类

| 痛点 | Agent Cowork 应该怎么帮 |
|---|---|
| 不知道 PPT 怎么分章节 | 自动生成 6-10 页结构 |
| 不会提炼重点 | 从文档/表格/聊天记录提炼成每页标题和要点 |
| 不会排版 | 一键统一标题、字号、间距、配色 |
| 不会找配图 | 本地素材优先，云端素材需确认来源 |
| 不会做图表页 | 从 Excel 数据自动生成图表页 |
| 不会写演讲稿 | 每页生成 30 秒讲稿 |
| 不会做封面结尾 | 自动生成正式封面和总结页 |
| 不会美化 | 提供“正式商务 / 简洁汇报 / 活泼培训 / 政企风”风格 |
| 不会压缩内容 | 自动把大段文字拆成要点 |
| 不会从 Word 转 PPT | 一键把文档转成可汇报 PPT |

### 4.4 文件整理类

| 痛点 | Agent Cowork 应该怎么帮 |
|---|---|
| 桌面乱七八糟 | 先生成整理方案，确认后移动副本 |
| 文件名乱 | 按日期/项目/客户/版本统一命名 |
| 找不到文件 | 建立本地索引，按自然语言搜索 |
| 不知道哪些文件有用 | 自动分成“重要 / 可能有用 / 重复 / 可归档” |
| 不敢删文件 | 默认不删除，只移动到“待确认归档” |
| 多版本混乱 | 自动识别最新版和历史版 |

### 4.5 邮件、群消息、会议类

| 痛点 | Agent Cowork 应该怎么帮 |
|---|---|
| 不会回邮件 | 生成 3 种语气草稿：正式、简短、委婉 |
| 不会总结群聊 | 提炼结论、待办、负责人、截止时间 |
| 不会写会议纪要 | 从录音稿/聊天/手写记录生成纪要 |
| 不会跟进客户 | 生成跟进话术、待办提醒、客户档案 |
| 忘记交周报 | 周五自动生成草稿并提醒 |
| 不会写请假/报销/申请 | 表单式输入，自动生成规范文本 |

## 5. 新首页：从“聊天框”改成“我想做什么”

### 5.1 首页结构

```txt
┌──────────────────────────────────────────────┐
│ 你好，今天要处理什么？                         │
│                                              │
│ [帮我做个表格] [帮我写个文档] [帮我做个PPT]     │
│ [整理一堆文件] [生成周报] [会议纪要]            │
│ [老板让我整理一下] [我也不知道该怎么弄]          │
│                                              │
│ 拖文件到这里：Word / Excel / PPT / PDF / 图片  │
│                                              │
│ 最近成果：                                     │
│ - 客户跟进表_已整理.xlsx                       │
│ - 本周周报_草稿.docx                           │
│ - 项目汇报PPT_可编辑.pptx                      │
└──────────────────────────────────────────────┘
```

### 5.2 首页不能出现的东西

```txt
- MCP
- Provider
- Model Router
- API Key
- Token
- JSON
- Shell
- Workspace Root
- Trusted Root
- Vector Index
- Prompt Cache
```

这些只放到“高级设置”。

### 5.3 首页必须出现的东西

```txt
- 大按钮
- 文件拖拽区
- 最近成果
- 常用任务
- 一句话输入框
- 新手示例
- 安全提示：默认不会改原文件
```

### 5.4 首页默认提示语

不要写：

```txt
请输入 prompt
```

要写：

```txt
你可以这样说：
- 帮我把这些表格合并成一个总表
- 帮我把这个 Word 改得正式一点
- 帮我用这些材料做一个 8 页 PPT
- 老板让我整理一下这些文件，我不知道怎么弄
```

## 6. 文件篮：小白最需要的入口

### 6.1 为什么要做文件篮

小白用户最大的真实行为是：

```txt
我把文件拖给你，你看着办。
```

所以需要一个“文件篮”，而不是文件树。

### 6.2 文件篮交互

用户拖入文件后，系统自动识别：

```txt
你放入了 12 个文件：
- 3 个 Word
- 4 个 Excel
- 2 个 PPT
- 2 个 PDF
- 1 张图片

我猜你可能想做：
[生成一份汇总报告]
[做一个汇报PPT]
[整理成表格]
[检查有没有重复/异常]
[按项目重新命名和归档]
```

### 6.3 文件篮的关键规则

```txt
1. 用户拖入文件只是“加入材料”，不是上传云端。
2. 默认复制到本地安全工作区，不移动原文件。
3. 默认只读分析，写入必须审批。
4. 所有产物输出到“成果”区。
5. 如果文件很多，先生成材料清单，让用户确认。
```

## 7. “老板让我整理一下”模式

这是非常重要的小白场景。

### 7.1 用户入口

```txt
[老板让我整理一下]
```

用户点进去后只问一个问题：

```txt
老板大概想要什么？
[一份文档]
[一个表格]
[一个PPT]
[一段回复]
[我不知道]
```

如果用户选“我不知道”，系统自动执行：

```txt
1. 读取材料类型。
2. 判断材料是否偏数据、偏文字、偏汇报。
3. 推荐 3 种可能交付物。
4. 展示样例预览。
5. 让用户选一个。
```

### 7.2 推荐逻辑

```txt
如果材料多为 Excel：推荐“汇总表 + 文字结论”。
如果材料多为 Word/PDF：推荐“汇总报告 + PPT”。
如果材料多为聊天记录：推荐“会议纪要 + 待办清单”。
如果材料多为图片/截图：推荐“OCR 提取 + 整理表”。
如果材料混杂：推荐“材料目录 + 摘要 + 风险/待办”。
```

### 7.3 输出样式

```txt
我建议你交这 3 个东西：

方案 A：一页总结
适合：老板只是想快速了解情况
产物：Word / PDF

方案 B：汇总表 + 结论
适合：材料里有数据、名单、金额、进度
产物：Excel + Word

方案 C：8 页汇报 PPT
适合：需要开会讲、给领导看
产物：PPT + 演讲稿
```

## 8. Office 急救中心

### 8.1 入口

首页新增：

```txt
[Office 急救]
```

进去后不是按软件分类，而是按问题分类：

```txt
你遇到了什么问题？
[表格乱了]
[公式不会写]
[Word 太丑]
[PPT 没思路]
[文件打不开]
[格式不统一]
[老板说不够正式]
[数据看不懂]
```

### 8.2 Excel 急救

#### 8.2.1 傻瓜化入口

```txt
你想对这个表做什么？
[算总数]
[按人/部门/月汇总]
[找重复]
[找异常]
[合并多个表]
[生成图表]
[把数据写成结论]
```

#### 8.2.2 不讲公式，讲结果

不要显示：

```txt
=SUMIFS(A:A,B:B,"销售部")
```

默认显示：

```txt
我已经帮你算出：销售部本月总金额是 128,450 元。
需要的话，我也可以把公式写进表格里。
```

高级模式才显示公式。

#### 8.2.3 Excel 输出策略

```txt
- 原始表不改。
- 生成“清洗后表格.xlsx”。
- 生成“异常数据清单.xlsx”。
- 生成“文字结论.md/docx”。
- 所有修改有预览。
```

### 8.3 Word 急救

#### 8.3.1 常见按钮

```txt
[变正式]
[变简短]
[改错别字]
[统一排版]
[生成目录]
[补充结构]
[生成摘要]
[转成通知]
[转成方案]
[转成会议纪要]
```

#### 8.3.2 Word 输出策略

```txt
原文件：会议记录.docx
新文件：会议记录_正式纪要_可交付.docx
附加：修改说明.md
```

### 8.4 PPT 急救

#### 8.4.1 常见按钮

```txt
[从0生成PPT]
[把Word转PPT]
[把表格做成PPT]
[美化现有PPT]
[生成演讲稿]
[压缩到10页]
[做成领导喜欢的风格]
```

#### 8.4.2 PPT 风格选择

对小白不要说“设计系统”，说：

```txt
你想要哪种感觉？
[正式商务]
[简洁清爽]
[政府/国企风]
[培训课件]
[销售提案]
[项目复盘]
```

#### 8.4.3 PPT 输出策略

```txt
- 生成可编辑 PPTX。
- 每页附带讲稿。
- 生成 1 页目录。
- 生成 1 页结论。
- 如果图表来自 Excel，保留数据来源说明。
```

## 9. 任务模板：小白只选模板，不写 Prompt

### 9.1 第一批必做模板

| 模板 | 用户按钮 | 输入 | 输出 |
|---|---|---|---|
| 一键周报 | 帮我写周报 | 本周文件/聊天/表格 | Word + 可复制文本 |
| 一键日报 | 帮我写日报 | 今天做的事 | 简短日报文本 |
| 会议纪要 | 生成会议纪要 | 录音稿/聊天记录/手写记录 | 纪要 + 待办 |
| 文件夹转 PPT | 用这些材料做 PPT | 文件夹 | PPTX + 讲稿 |
| Excel 清洗 | 表格乱了帮我整理 | Excel/CSV | 清洗后 Excel |
| Excel 汇总 | 帮我统计一下 | Excel | 汇总表 + 图表 |
| Word 正式化 | 改得正式一点 | 文档/口语文本 | 正式 Word |
| 通知公告 | 写个通知 | 简单事项 | 通知 Word/文本 |
| 客户跟进 | 帮我回客户 | 聊天/邮件/客户资料 | 回复草稿 |
| 报销整理 | 帮我整理报销 | 发票/截图/表格 | 报销清单 |
| 招聘筛选 | 帮我看简历 | 简历文件夹 | 候选人表 |

## 20. 兜底机制：小白不能被错误卡死

### 20.1 兜底层级

```txt
L1：原方案重试一次。
L2：换解析器 / 换模型 / 换本地简化流程。
L3：降级为纯文本/CSV/Markdown 草稿。
L4：生成操作指南，让用户手动完成最后一步。
L5：保存诊断包，允许用户发给懂技术的人。
```

### 20.2 Office 兜底例子

| 场景 | 兜底 |
|---|---|
| Excel 样式读取失败 | 只读取数据，生成 CSV + 文字结论 |
| Word 写入失败 | 生成 Markdown + 可复制正文 |
| PPTX 生成失败 | 生成大纲 + 每页文案 + 讲稿 |
| OCR 不可用 | 提示安装 OCR 包，或手动粘贴文字 |
| 模型失败 | 切换本地/备用模型，或用规则模板生成 |
| 能力包缺失 | 一键安装或简化模式继续 |
| 文件被占用 | 提示关闭文件，或另存为新文件 |

## 25. 新增 Hooks 规划：小白安全保护版

### 25.1 `BeginnerModeGuard`

目的：禁止在小白模式下暴露危险或技术操作。

```ts
type BeginnerModeGuard = {
  event: 'BeforeRenderAction' | 'PreToolUse' | 'BeforeApproval'
  rules: [
    'hide_shell_by_default',
    'hide_raw_json_by_default',
    'explain_file_write_in_plain_language',
    'require_preview_for_any_write',
    'require_duplicate_output_instead_of_overwrite'
  ]
}
```

### 25.2 `NoOriginalFileOverwriteHook`

```txt
任何 Word/Excel/PPT/PDF 任务，默认禁止覆盖原文件。
必须另存为：原文件名_处理后.xxx
```

### 25.3 `DraftOnlyExternalMessageHook`

```txt
邮件、微信、钉钉、企业微信、飞书消息默认只生成草稿，不自动发送。
```

### 25.4 `FriendlyErrorHook`

```txt
所有错误必须转换为：
1. 发生了什么
2. 影响什么
3. 用户可以点哪三个按钮
```

### 25.5 `DeliverableQualityGate`

```txt
交付前自动检查：
- 标题是否清晰
- 是否有结论
- 是否有错别字
- 是否格式统一
- 表格是否有表头
- PPT 是否每页过长
- 是否包含敏感信息
```

### 25.6 `SensitiveOfficeDataHook`

```txt
识别身份证、手机号、银行卡、客户名单、工资、合同金额等敏感字段。
如果要发送给云模型，必须提醒并让用户确认。
```

## 34. 最终结论

Agent Cowork 的下一阶段不应该继续堆“高级 Agent 能力”，而应该把能力包装成小白能理解的办公动作：

```txt
帮我写。
帮我整理。
帮我算。
帮我做PPT。
帮我改正式。
帮我给老板看。
帮我从一堆东西里弄出能交差的结果。
```

真正的壁垒不是模型有多强，而是：

```txt
1. 用户不懂办公也能完成。
2. 每一步都安全。
3. 失败也有草稿。
4. 原文件不会被破坏。
5. 结果能直接交差。
6. 下次能记住用户习惯。
7. 能按岗位逐步扩展能力。
```

这一版建议优先落地：

```txt
小白首页 + 文件篮 + 老板让我整理一下 + Office 急救 + 成果区 + 友好错误提示
```

只要这 6 件事做好，Agent Cowork 就会从“技术型 Agent 工作台”变成“普通白领每天愿意打开的办公助手”。
