# 08 · 企业机密档安全基线(threat model + 分档承诺 + 任务拆解)

> 目标:把"本地保密"从口号变成**可验证的企业级承诺**。安全工程不说"绝对保密",
> 只说明确威胁模型下的可验证边界——这也是企业安全评审的真实问法(数据出不出网?
> 落盘加密吗?能审计吗?供应链可信吗?)。

## 0. 分档承诺(产品分级,对外口径)

| 档位 | 承诺 | 模型路径 | 对应 securityMode |
| --- | --- | --- | --- |
| 标准档 | 数据仅发给用户选定的模型商,其余全本地 | 云 API | `controlled_hybrid`(默认) |
| 内网档 | 内容永不出企业边界,仅允许内网模型网关 | 内网 vLLM/网关 | `enterprise_local` + `KCW_CUSTOMER_MODEL_GATEWAY_HOSTS` |
| 隔离档 | 零出网,可被第三方验证 | 纯本机模型(Ollama/LM Studio 等) | `air_gap` + 机密总开关 |

## 1. 威胁模型(隔离档,防什么/不防什么)

**防**:①应用/工具链把工作区内容发到外网(模型调用、WebSearch/WebFetch、连接器、
OAuth、插件下载);②记忆/日志把凭据或敏感内容落到边界外(MASE 等外部后端);
③连接器/子进程作为旁路出网;④明文落盘被拷走(→ 切片 2);⑤应用层被绕过后的
出网(→ 切片 3,OS 级强制)。

**不防**(如实声明):恶意管理员/物理接触、OS 级恶意软件、供应链上游被投毒
(→ 切片 4 缓解)、用户主动复制粘贴外发。

## 2. 既有地基(已验证,不重复造)

- L0 `security-mode.ts`:`air_gap` 已在模型策略层拒绝非本地 provider
  (`decideModelProviderPolicy`),工具策略层拒绝 `network_external` 与非隔离沙箱执行
  (`decideToolPolicy`);出口统一走 `egress-gateway` + `egress-audit.jsonl`。
- 连接器路由只允许 host 内置项(任意 stdio 命令早已被拒);记忆读写双侧 DLP;
  路径 jail;防篡改审计链;凭据 DPAPI;零遥测(决策 D4)。
- 验证脚本已有雏形:`security:egress-zero` / `security:airgap` / `smoke:offline-local`。

## 3. 差距与切片(按用户确认的顺序逐个增强,一特性一提交)

### 切片 1 · 机密模式一键 profile(本期)
现状缺口:没有总开关;`air_gap` 需手工设且可被配置覆盖;**MASE 桥接装配不受安全
模式管**(`MASE_MCP_ENABLED=1` 时 air_gap 下仍会连外部记忆进程);OAuth 连接器路由
(`/api/connectors/oauth/*`)在 air_gap 下仍可发起 GitHub device flow。
交付:
- `KCW_CONFIDENTIAL=1` 总开关(L0 `security/confidential.ts`,纯函数):
  `resolveSecurityMode` 首先检查它并**强制返回 `air_gap`**,任何配置/env 都不能削弱
  (fail-closed;全部 L0 策略消费方自动继承)。
- `server.ts` 启动期 MCP 装配咽喉过滤:机密模式下丢弃所有启动 MCP 服务器(含 MASE),
  记录丢弃原因。
- 机密模式下 `/api/connectors/oauth/*` 一律 403(中文说明)。
- `/api/selfcheck` 暴露 `security.confidential`,自检项含机密模式状态(前端安全状态条
  随 securityMode=air_gap 已可见)。
- 单测矩阵 + `.env.example` 文档。
验收:host 测试全绿;设 `KCW_CONFIDENTIAL=1` 后云模型/外网工具/OAuth/MASE 全部
fail-closed,本地模型(openai/local)可用。

### 切片 2 · 落盘加密 + 一键销毁 + 保留期
现状缺口(2026-07-07 实测):`storage/`、`memory/` 零加密(仅 credential-store 有
DPAPI);对话/记忆/runs/checkpoints/trace 全明文;无 retention/purge。
交付:应用层加密(AES-GCM,密钥 DPAPI 包裹,复用 credential-store 模式)覆盖
SQLite/JSON 存储;"一键彻底销毁工作区数据"(runs/checkpoints/trace/记忆/审计可选);
保留期策略(N 天自动清理)。

### 切片 3 · OS 级出网强制 + 可验证零出网报告 —— 计划模块已交付,真机 apply 待验收
现状缺口:出口闸只在应用层;Shell/子进程/本地沙箱(`networkIsolated:false`)是旁路。
已交付(2026-07-07):
- L1 `security/egress-firewall.ts`(纯函数)+ 单测:按 app 可执行文件生成 program-scoped
  出站 Block + loopback/内网网关 Allow 的**可审查规则计划**,含 PowerShell 建规命令与
  一把回滚命令;非 IP 网关主机名不静默放行(要求 DNS pin,fail-closed)。
- `scripts/security-egress-firewall.ts`(`npm run security:egress-firewall-plan`):plan-only,
  写 `reports/security/egress-firewall-plan.json` 并打印命令,**不改本机防火墙、不需管理员**。
诚实边界(重要):Windows 防火墙 Block 优先于 Allow,纯 netsh/`New-NetFirewallRule` 规则
**无法完美表达"默认拒绝、仅放行白名单"**;要绝对默认拒绝需 WFP 带权重过滤器或机器级
出站默认拒绝策略。故本切片的 OS 强制是 **best-effort**,应用层出口网关(air_gap/机密模式,
已在切片 1 覆盖)仍是主执行点,二者构成纵深防御。
真机验收已完成(2026-07-07,`reports/security/egress-firewall-acceptance-20260707.md`):
- ✅ program-scoped 出站封锁对**直连外呼**真实有效(被锁进程直连 exit=7 被拦,本地模型
  127.0.0.1:11434 放行,未锁进程不受影响,`Remove-NetFirewallRule -Group` 回滚干净)。
- ❌ **根因发现:Windows 防火墙不过滤 loopback 流量**。隔离机若装了本机转发代理
  (http(s)_proxy=127.0.0.1:7897,如 Mihomo/Clash),被锁进程经代理即外呼成功(http=301)——
  netsh 层无法封堵此旁路(不是规则写法问题,是 Windows 既定行为)。收窄 loopback 端口对此无效。
- 结论(修订):**"隔离档零出网"除防火墙外的必要前提 = 机密档进程环境清除
  http_proxy/https_proxy/ALL_PROXY,或隔离机不装本机代理**;否则应用层出口网关(air_gap)
  仍是唯一可靠防线。已回写 `egress-firewall.ts` 根因 warning + `--loopback-port` 收窄选项
  (修 `-RemotePort` 需配 `-Protocol TCP`)。
- 后续(下一刀,已识别):机密模式在进程装配处主动剥离 http(s)_proxy 环境,把上面(a)从
  "部署须知"变成"代码强制";`security:egress-zero` 再纳入防火墙状态 + 代理环境探测。

### 切片 4 · 连接器签名治理 → CA 代码签名 → 渗透测试(外部条件,后置)

**连接器治理 —— 已达成(代码面,2026-07-07):** 机密档下连接器攻击面由三道闸锁死,
组合起来即"白名单/签名治理"的实质:
- ① 启动期 MCP(含 MASE)全丢(切片 1,`server.ts` 装配咽喉);
- ② `/api/connectors/oauth/*` 整面 403(切片 1);
- ③ `/api/connectors/connect` 只接受 host 内置(`buildConnectorSpec` 对客户端命令/未知
  连接器一律返回 400),而唯一可连的内置是本地 `filesystem`(无对外出站)。
  确认测试:`confidential-connector-posture.test.ts`。
故不存在"客户端注入任意 stdio 连接器出网"的旁路。进一步的密码学签名(对连接器清单做
Ed25519 签名校验)属增强项,当前 allowlist 已消除该威胁,签名留作 D2 决策后续。

**CA/EV 代码签名 —— 待外部条件(不可在本机完成,标"待外部"):** 需购买 EV 代码签名
证书(硬件令牌)。就位后在 `tauri.conf.json` 配 `windows.certificateThumbprint` 并在
release 流程签名 installer;`docs/RELEASE-CHECKLIST` 已留签名步骤位。无证书前分发的
是未签名包,SmartScreen 会告警——如实对朋友/客户声明。

**外部渗透测试 —— 待外部条件(需第三方,标"待外部"):** 交付证据包 = 威胁模型(本文档)
+ 零出网报告(切片 3 真机验收产物)+ 第三方渗透报告。渗透公司/预算就位后执行。

**供应链证据(可做部分,已具备):** `npm run audit:deps` 做依赖审计;仓库零运行时依赖
(仅 zod),node:sqlite 用内置,攻击面小;发布可附 SBOM。这些是渗透证据包里"供应链可信"
一节的本地可产出材料。
