# agent cowork 安全测试结果(Phoenix Scan)

> 测试日期:2026-06-07 · 工具:Phoenix Scan v2.0.0 · 目标:agent cowork 本地 Host(`http://127.0.0.1:3001`)

## 一句话结论
对 agent cowork 做了**保守(仅检测)**与**激进(redteam / 关闭鉴权 / 全能力)**两轮扫描,并对最危险接口做了定点利用验证。**未发现真实的高危 / 严重漏洞**:工具原始报出的 CRITICAL / HIGH 经逐条实测**全部为误报**;真实可改项仅 2 个低危加固(**均已于 2026-06-07 修复**,见文末)。应用核心安全边界(路径牢笼 / 鉴权 / 审批闸门)在激进无鉴权条件下**全部扛住**。

## 测试方法(隔离,未碰真实文件)
- 用临时目录作 `TRUSTED_ROOT` 与 `AGENT_COWORK_HOME`,**不加载真实 API key**(Kimi/Moonshot 关闭,无外联 / 计费)。
- 两轮:
  1. **保守**:`--mode conservative --strategy deep --depth 3 --modules all`(50 插件,无破坏性)。
  2. **激进**:`--profile redteam --mode aggressive --allow-exploit --allow-oast --allow-bruteforce --allow-destructive`,并 `KCW_REQUIRE_AUTH=false` 放开全部 `/api/*`(64 插件)。
- 全程隔离:扫描期间应用仅在临时目录写了自身 `auth.sqlite` / run 记录,**真实项目文件零改动**;扫完停服、删临时目录。

## 关键边界验证(全部扛住)
- **路径牢笼**:绝对路径越界、`../` 穿越、以及**客户端伪造 `trustedRoot`**(`C:/`、`C:/Windows`、甚至指向真实项目目录)全部被 `Path escaped trusted root` 拦下——**只能收窄、不能逃逸**。
- **鉴权**:开启时 `/api/*` 对匿名一律 401。
- **审批闸门**:`web.fetch`(及 sandbox / shell)= `risk:high + requiresApproval`,即使关掉鉴权也提示 "requires agent approval, cannot be called directly",写操作还强制 `Idempotency-Key`——SSRF / RCE 面被挡在审批之外。
- **危险方法**:PUT / DELETE / TRACE 实测全 404。
- **安全响应头**:已具备 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、COOP/CORP `same-origin`、`cache-control: no-store`;仅缺 CSP。

## 真实可改项 → 已修复(2026-06-07)
1. ✅ **补 `Content-Security-Policy` 响应头** —— 在 `apps/host/src/http/middleware/common.ts` 的 `SECURITY_HEADERS` 加入:
   `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`
   覆盖所有响应(含 SPA 与 /metrics)。**已用真实浏览器加载验证**:SPA 完整渲染、同源 API/SSE 正常、**无任何 CSP 违规**(唯一控制台报错是缺 `favicon.ico`,与 CSP 无关)。回归测试:`apps/host/test/server-security.test.ts` 新增「every response carries a Content-Security-Policy header」。
2. ✅ **`/metrics` 收口** —— 改为**默认关闭**:`apps/host/src/routes/system-routes.ts` 中,未显式设置 `KCW_METRICS_ENABLED=true` 时匿名 `GET /metrics` 返回 **404**;开启后仍像 `/health` 一样豁免鉴权,便于 Prometheus 抓取(安全默认 + 按需开启)。回归测试:`apps/host/test/metrics.test.ts` 改为「默认 404」+「开启后 200」两个用例。

> HSTS / "明文 HTTP" 不适用:本服务是 `127.0.0.1` 本地 sidecar,无 TLS 是设计如此(未改)。

## 顺带修复了 Phoenix Scan 自身的一个误报 bug
扫描中发现工具的**布尔盲注检测器**会被"每次响应带随机 token(traceId / UUID)"的接口骗:true / false 等长(`tf_diff=0`)却因随机串把相似度压到 `0.93 < 0.95` 阈值,从而误报"已确认 SQLi"。**已修复**(比较前剥离 UUID / 长 hex / 时间戳等易变 token),并补了回归测试,SQLi 测试套件全绿。
